# Cierre de producto 1.0: nombre visible e inicio

14/10/2026. Alcance limitado a los dos ajustes pedidos. Feature freeze de Blindly 1.0: nuevas ideas pasan a 2.0; sólo quedan QA, release y correcciones de fallos, seguridad o compatibilidad.

1. **Nombre visible:** Perfil → Editar nombre abre un editor integrado a la tarjeta. Guardar/Cancelar, explicación de que no es único, validación y mensajes ES/EN/PT. Entre 1 y 30 puntos de código Unicode; trim, acentos, números, espacios y emojis. Rechaza vacío, espacios Unicode, controles, saltos, dirección bidireccional y UTF-16 inválido. Un emoji compuesto puede ocupar varios puntos de código.
2. **Almacenamiento:** `auth.users.raw_user_meta_data.display_name`, mediante `supabase.auth.updateUser({data:{display_name}})`. Supabase mezcla metadata; no cambia UUID, email, password, provider ni identidad externa. Preferencia display_name → full_name → name/nombre legacy → alias propio de liga como fallback de Perfil → Jugador. No hay tabla perfiles ni unicidad.
3. **Invitado:** editor gratuito, misma identidad anónima. El nombre persiste en su sesión y al proteger ese UUID. Borrar la instalación sin proteger la cuenta sigue teniendo el límite previo de recuperación; no se cambió Auth.
4. **Google:** el alias de Blindly prevalece sobre full_name; éste y la foto/metadata de Google se conservan. El servicio se probó con fixtures de Google y el flujo OAuth Android previamente cerrado no se modificó. No se repitió un consentimiento Google real en este bloque.
5. **Ligas:** trigger privado de Auth sincroniza sólo las membresías activas propias en ligas activas dentro de la misma transacción de metadata. Si falla, Auth no confirma un guardado parcial. Otro trigger conserva display_name ante altas/actualizaciones de alias de mesa, evitando que una mano posterior restablezca un alias viejo. No modifica roles, ownership, títulos, otros jugadores ni membresías inactivas/ligas archivadas. RPC `actualizar_mi_nombre_visible(p_nombre)` disponible para reparación idempotente, auth.uid únicamente y nombre consistente con metadata; sin parámetro de usuario. No requiere Plus ni cuenta protegida.
6. **Ranking:** sigue leyendo liga_miembros.nombre. Prueba SQL con resultado completo demuestra el alias nuevo con los mismos resultados; las fórmulas y criterios de clasificación existentes no se cambiaron. El desempate previo que usa nombre conserva su comportamiento.
7. **Históricos:** no hay UPDATE de puntuacion_partidas ni recaps. Prueba SQL verifica que nombre_jugador histórico permanece intacto. Los snapshots de partidas y la mesa en curso mantienen el alias que tenían; cambiar el perfil no altera acciones ni stacks.
8. **Perfil:** identidad propia aun sin club, inicial Unicode, nombre centrado y adaptable, badge Free/Founder Trial/Blindly Plus según fuente de acceso. El editor se oculta si cambia el UUID y el servicio valida la identidad esperada. Bloqueo de doble toque; ante error conserva borrador y permite reintentar. Formularios de crear/unirse a mesa y liga precargan el nombre de Auth sin pisar una edición manual o un nombre recibido por enlace.
9. **Fondo:** `src/components/AmbienteHome.tsx`, composición vectorial original: paño, borde de mesa, dos cartas, pila de fichas y luz champagne. Sólo dentro del hero del Inicio; no se monta en Perfil, formularios ni ligas.
10. **Fuente/licencia:** código e ilustración originales hechos para Blindly, distribuidos bajo MIT del repositorio. Sin imágenes descargadas, marcas de casinos, stock ni fuentes gráficas externas.
11. **Tamaño:** aproximadamente 2,5 KB de fuente antes de compresión; cero nuevos archivos bitmap y cero descargas remotas. Cambios posteriores de formato pueden variar unos bytes.
12. **Optimización:** usa react-native-svg ya instalado; sin nuevas dependencias, video, GIF, WebView, blur ni animación continua. Gradientes y geometría estáticos, sin textura raster sobredimensionada.
13. **Overlay:** rectángulo carbon con opacidad 0,80 sobre toda la ilustración. Es parte del SVG, sin interceptar controles. Los paneles y CTA usan las superficies originales.
14. **Home:** conserva logo, navegación, Plus, resumen real de liga, instrucciones y textos. Crear partida sigue siendo el CTA dorado dominante y Unirme con código secundario. No agrega datos ficticios a producción.
15. **Responsive:** viewBox 600×600 con `xMidYMid slice`: recorte proporcional sin distorsión. Mantiene maxWidth 620 del layout y safe areas existentes. UI web real verificada a 320×740, 430×932 y 768×1024, ES/EN/PT, con/sin liga y Free/Founder/reviewer. No hubo overflow horizontal ni excepciones de página. Es QA de navegador, no certificación física iOS/Android.
16. **Performance:** composición pequeña y sin actualizaciones periódicas propias. No agrega llamadas a red al Home; Nombre visible escucha Auth y usa la sesión persistida. No se midieron FPS o memoria de un dispositivo físico en este bloque.
17. **Accesibilidad:** ilustración decorativa con pointerEvents none y oculta a lectores de pantalla. Botones usan roles/labels/disabled existentes; editor usa Campo etiquetado, retorno de teclado y anuncio de éxito/error. Nombre largo envuelve en la tarjeta. Capa del 80% da contraste conservador >4,5:1 para texto secundario de los tres temas, incluso suponiendo un píxel blanco debajo; CTA mantiene su contraste previo. No se repitió TalkBack físico.
18. **Tests:** npm test completo, nuevas suites nombre-visible.cjs, nombre-visible-sql.cjs y perfil-nombre-ui.cjs. Cubren cuatro identidades, metadata/UUID, Unicode, límites, offline, doble toque, cambio de cuenta, RLS, RPC propio, rollback, sincronización, ranking e históricos. Las suites existentes de Auth, ligas, Founder y compras siguen incluidas. SDK real descartable confirmó guardado/refresh/rechazo/protección legacy/sincronización de liga; cleanup verificado sin usuarios ni ligas QA residuales. Google real y password real usan la evidencia previa, no fixtures como sustituto de una nueva prueba física.
19. **Typecheck:** npm run typecheck.
20. **Lint:** npm run lint. Sin dependencias nuevas ni refactor de monetización.
21. **CI:** workflow Verificar Blindly ejecuta Expo check/Doctor, auditoría crítica, TypeScript, lint, npm test y bundles web/Android/iOS. [Consultar las ejecuciones de main](https://github.com/ArgerichFacu/Blindly/actions/workflows/verify.yml). El cierre de entrega exige comprobar el resultado del commit demo publicado; el informe final de la sesión identifica esa ejecución.
22. **Pendientes/límites:** estos cambios requieren el siguiente binario; la APK/AAB v29 no los contiene. No se genera un AAB definitivo antes de la aceptación visual nativa. Sigue pendiente aceptación física ARM64/16 KB e iOS, y completar la declaración de Seguridad de los datos de Play que quedó en borrador cuando se cambió de bloque. Los avisos previos de Supabase (pg_net, políticas de cron y protección de contraseñas filtradas) no se alteraron; advisors agrega la RPC definer autenticada intencional, con auth.uid y nombre cotejado, sin abrir los helpers privados. No se activa RevenueCat, cobros ni se publica producción.
